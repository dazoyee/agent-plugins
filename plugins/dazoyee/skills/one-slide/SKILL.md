# one-slide

結論を先に示し、1枚のスライドだけで内容を伝える。
読み手がぱっと見て主題と要点をつかめる構成にする。

## 素材と情報量

会話の内容と、ユーザーが指定した Markdown・コード・既存文書の両方を素材にする。
出力は常に1枚にする。
情報が収まらない場合は優先度の低い内容から削り、削った内容を完了時の応答で箇条書きにする。

## レイアウト

上部に結論を表す一文を見出しとして置く。
本文には [`${CLAUDE_SKILL_DIR}/references/layouts.md`](${CLAUDE_SKILL_DIR}/references/layouts.md) の3つの型から、内容に合うものを1つ選ぶ。
根拠や独立した要点を伝える場合は「要点ブロック」を選ぶ。
案や状態の違いを見せる場合は「比較・対照」を選び、推奨案を強調する。
手順や時間の順序を伝える場合は「流れ・手順」を選ぶ。

## 表示とスタイル

HTML 1ファイルで完結させ、CSS・表・図はインラインで書く。
CDN・Web フォント・外部画像・JavaScript ライブラリを使わない。
フォントには OS 標準の日本語フォントを並べた `font-family` を指定する。
1920×1080 相当の16:9固定キャンバスを画面幅に合わせて拡大縮小し、スクロールを出さない。
白背景とアクセント1色の固定テーマを使い、依頼があればアクセント色を変える。
ダークモードには対応しない。
印刷や PDF 化でも16:9のまま出力できるよう `@page` と印刷用 CSS を設定する。

## 読みやすさ

本文の文字サイズは画面上で24 px 相当を下限にする。
1ブロックは見出しを除いて最大5行にする。
スライド全体の文字量は見出しを含めて日本語300字程度までを目安にする。
情報を詰め込むより、重要な関係が一目で分かる配置を優先する。

## 出力先

保存先の指定がなければ作業ディレクトリに `<主題>-slide.html` の名前で保存する。
主題は英小文字とハイフンで表す。
同名ファイルがある場合は上書きせず、別名にするかユーザーに確認する。

## 検証

`playwright-cli` で HTML を開き、1920×1080 の画面でスクリーンショットを撮る。
スクリーンショットで、はみ出し・重なり・文字の小ささを確認し、問題があれば修正する。
スクリーンショットは作業ディレクトリを汚さない場所に保存する。
HTML のあるディレクトリを localhost 限定の HTTP サーバーで配信し、次のコマンドをこの順に実行する。
`<ポート>`、`<HTMLのあるディレクトリ>`、`<ファイル名>`、`<作業ディレクトリ外の一時ディレクトリ>`、`<名前>` は対象に合わせて置き換える。
サーバーはバックグラウンドで起動し、検証後に停止する。
`file:` URL の制限を外す設定は使わない（ブラウザーにローカルファイル全体を読ませないため）。

```powershell
$server = Start-Process python -ArgumentList '-m','http.server','<ポート>','--bind','127.0.0.1','--directory','<HTMLのあるディレクトリ>' -PassThru
playwright-cli open http://127.0.0.1:<ポート>/<ファイル名>
playwright-cli resize 1920 1080
playwright-cli eval '() => { const s = document.querySelector(".slide"); return s.scrollHeight <= s.clientHeight && s.scrollWidth <= s.clientWidth; }'
playwright-cli screenshot --filename=<作業ディレクトリ外の一時ディレクトリ>/<名前>.png
playwright-cli close
Stop-Process -Id $server.Id
```

`playwright-cli` または Python が使えない環境では検証を飛ばし、完了時の応答でその旨を伝える。
`playwright-cli eval` の結果が `false` の場合は情報を削って作り直す。

## 完了時の応答

作成したファイルのパス、選んだレイアウト、削った情報、検証結果を伝える。
削った情報がある場合は箇条書きにする。
