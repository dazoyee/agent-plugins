# CONTRIBUTING.md の標準構成

GitHub のコミュニティ健全性ファイルとしての CONTRIBUTING.md と、[Open Source Guides](https://opensource.guide/how-to-contribute/) の構成をもとにする。
読み手は「このリポジトリの開発に参加する人間」。手順どおりに進めれば、環境を作って変更を入れ、PR を出せることを目指す。
GitHub は CONTRIBUTING.md をルート・`docs/`・`.github/` のいずれかから認識する。既存の場所があればそこを使い、無ければルートに置く。

## 節の構成

上から順に並べる。「任意」の節は、該当する内容があるときだけ置く。

| 節 | 必須 | 書くこと |
|---|---|---|
| はじめに | 任意 | 参加を歓迎する一言と、この文書で分かること |
| 行動規範 | 任意 | CODE_OF_CONDUCT.md があればリンクする |
| 質問・不具合報告・機能要望 | 任意 | どこに、どの形式で出すか。issue テンプレートがあればそれを案内する。脆弱性は SECURITY.md の窓口へ |
| 開発環境の構築 | 必須 | 前提ツール（版は定義元のファイルを示す）、クローン後の初期化コマンド |
| ビルド・テスト・lint | 必須 | CI と同じコマンドを、そのまま実行できる形で。単一テストの実行方法もあれば書く |
| コーディング規約 | 任意 | formatter・linter の設定ファイルを示す。ツールで強制されない約束だけを文章で書く |
| コミットメッセージ | 任意 | 規約（Conventional Commits など）と例 |
| ブランチと PR の流れ | 必須 | ブランチの切り方、PR を出す前に通すこと、PR テンプレートの有無 |
| レビューとマージ | 任意 | 誰がレビューするか、マージの条件 |
| リリース | 任意 | 版の上げ方・公開手順。参加者が関わる場合だけ |

1人で開発する個人用リポジトリなら、「質問・不具合報告」「レビューとマージ」は省いてよい。

## 置かないもの

- プロダクトの使い方 → README.md
- エージェント固有の指示（エージェントだけが必要とする注意点・完了条件） → AGENTS.md / CLAUDE.md
- 規約の全文の書き写し → 設定ファイルや外部の規約へリンクする

## チェックリスト

- [ ] 環境構築からテスト実行まで、書かれた順に実行すれば動く
- [ ] ビルド・テスト・lint のコマンドが CI の実物と一致している
- [ ] 前提ツールの版を直書きせず、定義元を示している
- [ ] formatter・linter で強制されている規約を文章で重複して書いていない
- [ ] コミット規約が `git log` の実際の書き方と一致している
- [ ] README.md や AGENTS.md と同じ手順を重複して書いていない
- [ ] 時制表現・進捗・TODO が無い
