# README.md の標準構成

[standard-readme](https://github.com/RichardLitt/standard-readme) と [Make a README](https://www.makeareadme.com/) の構成をもとにする。
読み手は「このリポジトリを初めて開いた利用者」。数十秒で「これは何か」「自分に関係あるか」「どう使い始めるか」が分かることを目指す。

## 節の構成

上から順に並べる。「任意」の節は、該当する内容があるときだけ置く。

| 節 | 必須 | 書くこと |
|---|---|---|
| タイトル | 必須 | リポジトリ名（またはプロダクト名）を `#` 見出しで |
| 概要 | 必須 | タイトル直下に1〜2文。何をするもので、誰のためのものか |
| バッジ | 任意 | CI の状態やパッケージの版など、実在するものだけ |
| 目次 | 任意 | README が長く、節が多いときだけ |
| 背景・特徴 | 任意 | なぜ作ったか、類似のものと何が違うか |
| インストール | 必須 | 前提条件（必要なツール。版は定義元のファイルを示す）と導入コマンド |
| 使い方 | 必須 | 最小の実行例。コマンドやコードをそのまま試せる形で |
| 設定 | 任意 | 設定ファイル・環境変数・オプション |
| 貢献 | 任意 | CONTRIBUTING.md へのリンク。本文は書かない |
| ライセンス | 必須 | ライセンス名と LICENSE ファイルへのリンク。LICENSE が無ければ書かずにユーザーへ確認する |

個人用・社内用のリポジトリで「貢献」「ライセンス」が不要なら省いてよい。省いた理由は完了報告で触れる。

## 置かないもの

- 開発環境の構築・ビルド・テスト・コーディング規約・コミット規約・PR の流れ → CONTRIBUTING.md（小さなリポジトリでも README には置かない）
- エージェントへの指示 → AGENTS.md / CLAUDE.md
- 変更履歴 → CHANGELOG.md やリリースノート
- 詳細な設計や API の全仕様 → `docs/` などに置いてリンクする

## チェックリスト

- [ ] 冒頭の1〜2文で、何をするものか分かる
- [ ] インストールと使い方のコマンドが、マニフェストや CI の実物と一致している
- [ ] 前提ツールの版を直書きせず、定義元を示している
- [ ] 開発者向けの手順（環境構築・ビルド・テスト）を書いていない
- [ ] リンク先（CONTRIBUTING.md・LICENSE・docs）が実在する
- [ ] バッジ・URL・連絡先が実在する
- [ ] 時制表現・進捗・TODO が無い
