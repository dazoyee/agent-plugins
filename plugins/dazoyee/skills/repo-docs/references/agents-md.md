# AGENTS.md・CLAUDE.md の標準構成

## AGENTS.md

[AGENTS.md](https://agents.md/) の形式に従う。Codex・Cursor・GitHub Copilot など多くのコーディングエージェントが読む、エージェント向けの README にあたる。
必須の節や書式は無く、ただの Markdown でよい。
読み手は「このリポジトリで作業するエージェント」。人間向けの文書には書かれないが、知らないと間違える情報を渡すことを目指す。

### 仕様上の振る舞い

- エージェントは作業中のファイルに最も近い AGENTS.md を優先する。モノレポでは、サブプロジェクトごとの差分をそのディレクトリの AGENTS.md に書き、ルートには全体に共通することだけを書く。
- ユーザーがチャットで出した指示は AGENTS.md より優先される。
- AGENTS.md に書かれた検証コマンドは、エージェントが変更後に実行しようとする。実行してよいコマンドだけを書く。

### 節の構成

決まった構成は無いので、次の中から該当するものを置く。節の数より、1行ごとの具体性を優先する。

| 節 | 書くこと |
|---|---|
| 概要 | 1〜3行。詳細は README.md を参照させる |
| 構成 | 主要ディレクトリの役割。生成物・vendor など触ってはいけない場所 |
| 開発と検証 | 「ビルドとテストは CONTRIBUTING.md の〈節名〉に従う」という参照と、変更後に必ず通すコマンド（完了条件）。手順の全体は書かない。エージェント固有の注意（対話的なコマンドの代わりに使うフラグ、時間のかかるテストの扱いなど）があれば足す |
| 規約 | lint で強制されない暗黙知だけ。命名・層の分け方・使ってはいけない API など |
| 落とし穴 | 過去に間違えやすかった点。「〇〇は△△なので□□する」と理由を添えて |
| コミットと PR | CONTRIBUTING.md の規約を参照し、エージェントに守らせたい差分だけ |
| セキュリティ | 秘密情報の置き場所、読んではいけないファイル、外部に送ってはいけないもの |

### 書き方

- 命令形で、具体的に書く。「テストを書く」ではなく「`src/` を変えたら `tests/` の同名ファイルにテストを足す」。
- 守らせたい理由を1文添える。理由が分かると、エージェントは書かれていない場面にも応用できる。
- エージェントが言われなくても守る一般論（「読みやすいコードを書く」「エラー処理をする」）は書かない。

## CLAUDE.md

Claude Code は AGENTS.md を自動では読まず、CLAUDE.md を読む。
CLAUDE.md の中に書いた `@パス` は起動時に展開されるので、AGENTS.md を取り込んで共通の正本にする。
シンボリックリンクで AGENTS.md と CLAUDE.md を同じファイルにする方法もあるが、Windows や一部の Git 設定で壊れやすく、Claude Code 固有の指示を足す場所も無くなるため使わない。

### 構成

```markdown
@AGENTS.md

## Claude Code

<Claude Code 固有の指示だけ>
```

Claude Code 固有として置くもの。

- このリポジトリで使うスキル・スラッシュコマンド・サブエージェントと、使う場面
- hooks の動き（自動で走る処理があるなら、それを前提にした指示）
- `.claude/settings.json` の権限設定に関わる注意
- `.claude/rules/` など、他に取り込むファイルの `@パス`

固有の指示が無ければ、CLAUDE.md は `@AGENTS.md` の1行だけでよい。
個人の好み（口調・通知など）はリポジトリに置かず、各自の `~/.claude/CLAUDE.md` に書く。

### 既存の CLAUDE.md だけがある場合

内容を「他のエージェントにも役立つもの」と「Claude Code 固有のもの」に分け、前者を AGENTS.md に移して CLAUDE.md を上の構成にする。
ファイル構成の変更にあたるので、点検の指摘一覧に載せて承認を得てから行う。

## チェックリスト

- [ ] AGENTS.md と CLAUDE.md に同じ内容が重複していない
- [ ] CLAUDE.md が `@AGENTS.md` を取り込んでいる（AGENTS.md があるとき）
- [ ] CLAUDE.md に Claude Code 固有でない指示が無い
- [ ] README.md・CONTRIBUTING.md の手順を転記せず、参照している（変更後に必ず通すコマンドだけは直接書く）
- [ ] 書かれたコマンド・パス・ディレクトリが実在する
- [ ] 一般論・エージェントが言われなくても守ることが無い
- [ ] 指示に理由が添えられている
- [ ] 時制表現・進捗・TODO が無い
